# Тестирование установщика

Быстрый набор требует Python 3.11 или новее и PyYAML. Он проверяет разбор YAML, генерацию путей, обработку DNS, поиск занятых портов, синхронизацию времени и восстановление базы при ошибке.

```sh
python3 -m unittest discover -s tests -v
```

Полный прогон запускается с обычного компьютера или CI-раннера с Docker.

```sh
./tests/sandbox/run.sh
```

Скрипт собирает контейнеры Debian 12 и 13 и запускает тесты через отдельный Docker daemon внутри привилегированного контейнера. Docker-сокет хоста в этот контейнер не передаётся. Репозиторий монтируется только для чтения, временные файлы и образы дочерних контейнеров удаляются по завершении. Для первого прогона нужен доступ к реестрам образов и репозиториям Debian.

| Набор | Что проверяет |
| --- | --- |
| `tests/test_*.py` | Быстрые проверки данных и ошибки внешних команд через моки. |
| `tests/functional/` | Публичные команды CLI, локальный запуск `install.sh` и загрузку установщика через локальный HTTPS. |
| `tests/integration/` | Реальные контейнеры 3x-ui, Caddy, Certbot и Pebble. Запросы через Xray идут к локальному HTTPS-сайту с тестовыми сертификатами. |

Интеграции подставляют локальные DNS-имена и тестовые сертификаты. Установку пакетов Docker, NTP и запуск юнитов systemd проверяют быстрые тесты с подменой системных команд.

Совмещённый отчёт записывается в `coverage-report/coverage.txt` и `coverage-report/coverage.json`. Команда возвращает ненулевой код, если упал тест или покрытие строк либо ветвей ниже 95%. В проценты входит производственный код Python в `setup3ui`. Инструкции для новых тестов находятся в [AGENTS.md](../AGENTS.md).

## GitHub Actions

Workflow [Tests and Caddy image](../.github/workflows/ci.yml) запускает ту же песочницу при push, в pull request и при ручном запуске. Отчёты сохраняются в артефакте `coverage`. В Actions команда `run.sh --report-only` формирует отчёт, а отдельная задача проверяет оба порога в 95%. Обычный локальный запуск выполняет обе проверки сам.

## Выпуск версии

Перед выпуском перенеси заметки из `[Unreleased]` в датированную секцию `[X.Y.Z] - YYYY-MM-DD` в [CHANGELOG.md](../CHANGELOG.md). После push тега `vX.Y.Z` и успешного прогона тестов workflow публикует образ `ghcr.io/theillarion/easy-3x-ui-caddy` для Linux `amd64` и `arm64`. Один тег образа совпадает с Git-тегом, например `v1.0.0`. Второй тег имеет вид `sha256-<хеш Caddy.Dockerfile>` и связывает установщик с подходящей сборкой. После проверки образа на обеих архитектурах workflow создаёт GitHub Release с заголовком из тега и текстом из секции этой версии.

При чистой установке используется локальный образ, если он уже есть. В остальных случаях установщик пробует скачать готовый образ. Если скачать его не удаётся, выполняется локальная сборка. Команда `update --component caddy` обновляет образ под именем из действующего Compose и при сбое запуска возвращает предыдущий образ. После первой публикации выставь пакету в GHCR видимость **Public**, чтобы серверы скачивали его без входа в реестр.
