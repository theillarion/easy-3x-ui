# Конфигурация easy-3x-ui

Передай входной файл командой `sudo ./install.sh --config /absolute/path/config.yml`. После установки рабочая копия по умолчанию находится в `/opt/3x-ui/config.yml`. Начальные учётные данные и одноразовые команды остаются во входном файле. При чистой установке утилита генерирует пути панели и подписок и один раз показывает API-токен узла. Адреса панели и подписок также показывает `sudo setup-3x-ui status`.

В столбце «Режим HTTPS» значение «Оба» означает `certbot` и `caddy`.

## Сервер, HTTPS и учётные данные

| Поле | Режим HTTPS | Формат и значение по умолчанию | Когда заполнять и что меняется |
| --- | --- | --- | --- |
| `https` | Оба | `certbot` или `caddy`. По умолчанию `certbot`. | В режиме Certbot TLS обслуживает 3x-ui. В режиме Caddy он обслуживает HTTPS на внешнем `443` и передаёт HTTP на локальные порты панели и подписок. |
| `domain` | Оба | Доменное имя, например `vpn.example.com`. | От него строятся имена по умолчанию. Можно задать имена сервисов явно, с учётом требований `reality_address` и `cdn[].origin`. |
| `panel_domain` | Оба | Доменное имя. По умолчанию `master.<domain>`. | Имя панели. Обязательно без `domain`. |
| `subscription_domain` | Оба | Доменное имя. По умолчанию `gateway.<domain>`. | Имя подписок. Обязательно без `domain`. Должно отличаться от `panel_domain`. |
| `email` | Оба | Email, например `ops@example.com`. | Обязательный контакт ACME для выпуска сертификатов. |
| `docker_user` | Оба | Имя существующего обычного пользователя Linux. По умолчанию `SUDO_USER`. | Утилита добавит его в группу `docker` и откроет на чтение файлы каталога установки, включая базу, бэкапы и сертификаты. При запуске из root-сессии без `SUDO_USER` укажи имя явно. |
| `install_dir` | Оба | Абсолютный путь. По умолчанию `/opt/3x-ui`. | Каталог установки. Для чистой установки он должен быть новым, а его родительский каталог должен существовать. Для доступа без sudo родительский каталог должен пропускать `docker_user`. |
| `panel_port` | Оба | Целое число. По умолчанию `2053`. | Порт панели. В режиме Caddy доступен на loopback, а пользователь подключается к Caddy на `443`. |
| `subscription_port` | Оба | Целое число. По умолчанию `2096`. | Порт подписок. В режиме Caddy доступен на loopback, а пользователь подключается к Caddy на `443`. |
| `admin_username` | Оба | Непустая строка. | Логин для новой базы или сброса через YAML. Для изменения инбаундов укажи текущий логин. При чистой установке из бэкапа сохраняется логин из базы. |
| `admin_password` | Оба | Непустая строка. Пароль лучше брать в кавычки. | Пароль для соответствующего логина. При чистой установке из бэкапа сохраняется пароль из базы. |

## TCP REALITY и прямой XHTTP

| Поле                   | Режим HTTPS | Формат и значение по умолчанию                                      | Когда заполнять и что меняется                                                                                                                                   |
| ---------------------- | ----------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reality`              | Оба         | `true` или `false`. По умолчанию `false`.                           | Включает VLESS TCP REALITY.                                                                                                                                      |
| `reality_port`         | `certbot`   | Целое число. По умолчанию `443`.                                    | Внешний порт TCP REALITY при `reality: true`.                                                                                                                    |
| `reality_backend_port` | `caddy`     | Целое число. По умолчанию `8444`.                                   | Локальный порт Xray при `reality: true`. Клиент подключается к Caddy на внешнем `443`.                                                                           |
| `reality_address`      | `caddy`     | Доменное имя. По умолчанию `domain`.                                | Адрес сервера в клиентской ссылке TCP REALITY при `reality: true`. Если `domain` отсутствует, укажи его явно.                                                    |
| `reality_sni` | Оба | Непустой список доменных имён. Если `reality_sni_auto` опущен, по умолчанию `[www.cloudflare.com]`. | Имена для обоих REALITY-инбаундов. Первое применённое имя используется в настройках клиента. При `reality_sni_auto: true` явно задай здесь запасные имена. Установщик проверит их по порядку, если поиск не даст результата. При TCP REALITY за Caddy исключаются имена сайтов Caddy. |
| `reality_target` | Оба | `домен:порт`. По умолчанию первый `reality_sni` с портом `443`. | Целевой TLS-сервер для обоих REALITY-инбаундов. При `reality_sni_auto: true` опусти это поле. Установщик подставит выбранное имя и порт `443`. |
| `reality_sni_auto` | Оба | `true` или `false`. По умолчанию поле отсутствует. | `true` включает автоподбор. При `false` явно задай `reality_sni`, чтобы проверить каждое имя с заданным или вычисленным `reality_target`. Если поле опущено, YAML применяется без сетевой проверки SNI. |
| `reality_sni_scan` | Оба | `top10` или `scanner`. По умолчанию `top10`. | При `reality_sni_auto: true` выбирает способ поиска. `top10` проверяет фиксированный список из десяти публичных доменов, включая Apple, NVIDIA, Microsoft и Cloudflare. `scanner` скачивает RealiTLScanner, сканирует TCP/443 в IPv4-подсети и извлекает имена из сертификатов. Оба режима проверяют имена на TLS 1.3, HTTP/2, X25519 и доверенный сертификат с таймаутом 5 секунд на имя. Из подходящих имён первым предлагается самое быстрое по времени TLS-подключения. |
| `reality_sni_scan_cidr` | Оба | IPv4 CIDR, например `192.0.2.0/28`. По умолчанию подсеть интерфейса основного маршрута VPS. | Задаёт диапазон для `scanner`. Если у интерфейса только адрес с префиксом `/32`, укажи подсеть явно. |
| `reality_sni_scan_timeout` | Оба | Положительное целое число секунд. По умолчанию `30`. | Ограничивает время работы `scanner`. По истечении таймаута установщик проверяет имена, которые сканер успел найти. |
| `direct_xhttp`         | Оба         | `true` или `false`. По умолчанию `false`.                           | Включает прямой VLESS XHTTP REALITY.                                                                                                                             |
| `direct_xhttp_port`    | Оба         | Целое число. По умолчанию `8443`.                                   | Внешний порт прямого XHTTP REALITY.                                                                                                                              |
| `direct_xhttp_path`    | Оба         | `/`, путь с начальным `/` или `generate`. По умолчанию `/`.         | Путь прямого XHTTP. `generate` создаёт путь вида `/media/hls/<случайная часть>/index.m3u8`.                                                                      |
| `reality_tag` | Оба | Непустая строка. Для нового инбаунда по умолчанию `xray-tls-reality-<внешний порт>`. | Тег TCP REALITY. При изменении существующего инбаунда укажи его текущий тег. |
| `direct_xhttp_tag` | Оба | Непустая строка. Для нового инбаунда по умолчанию `xray-xhttp-reality-<внешний порт>`. | Тег прямого XHTTP REALITY. При изменении существующего инбаунда укажи его текущий тег. |

Порты задаются целыми числами от `1` до `65535`. У используемых портов должны быть разные значения. Установщик резервирует `80` под HTTP-01 и в режиме Caddy использует внешний `443` для HTTPS и TCP REALITY. В XHTTP-путях допустимы латинские буквы, цифры и символы `_`, `.`, `~` и `-`. Параметры после `?`, сегменты `.` и `..` и завершающий слэш для непустого пути проверка отклонит. Теги и примечания инбаундов показывает команда `status`. Если тег для нового инбаунда пропущен, установщик добавляет внешний порт автоматически. Например, с Caddy получатся `xray-tls-reality-443` и `xray-xhttp-reality-8443`. При `direct_xhttp_port: 9443` второй тег будет `xray-xhttp-reality-9443`. Явно заданный тег используется как есть. При повторном запуске с пропущенными тегами утилита использует сохранённые значения. При восстановлении сохраняются теги из базы.

## Подбор REALITY SNI

При включённом TCP REALITY или прямом XHTTP REALITY мастер предлагает
`top10`, `scanner` или ручной ввод. Если введённое имя не проходит
проверку, мастер предлагает результаты `top10`. На действующей установке
запусти `sudo setup-3x-ui reality-sni` или выбери `reality-sni` в меню.
При восстановлении базы выполни подбор после восстановления.

Пример YAML для установки или перенастройки с поиском в подсети VPS.

```yaml
reality_sni_auto: true
reality_sni_scan: scanner
# reality_sni_scan_cidr: 192.0.2.0/28
reality_sni_scan_timeout: 30
reality_sni: [www.cloudflare.com, www.microsoft.com]
```

При запуске из YAML установщик берёт самый быстрый подходящий результат
поиска или первое подходящее запасное имя. Если ни одно имя не подойдёт,
он завершится с ошибкой до применения настроек. Рабочий `config.yml`
хранит выбранные SNI и target. Для `render-caddy` используй рабочий
конфиг, а для `validate` подходит также исходный YAML с параметрами поиска.

## CDN

`cdn` — список маршрутов XHTTP через CDN. Каждая запись с `- provider:` создаёт один отдельный инбаунд Xray и один маршрут Caddy. Если TCP REALITY и XHTTP REALITY идут напрямую на сервер, укажи `cdn: []` или пропусти поле.

### Один CDN через Caddy

Добавь этот фрагмент в конфиг установки и подставь свои имена.

```yaml
https: caddy
domain: example.com
cdn:
  - provider: selectel
    edge: edge.example.com
    origin: node.example.com
    path: /media/hls/9636f214/index.m3u8
```

Как идёт запрос:

```text
Клиент → edge.example.com:443 (CDN)
       → node.example.com:443 (Caddy на твоём VPS)
       → 127.0.0.1:8080 (Xray на том же VPS)
```

- `provider` — шаблон XHTTP. Для одной записи выбери `selectel` или `yandex`.
- `edge` — публичный домен, который ты настроил у CDN-провайдера. Утилита записывает его в настройки инбаунда для клиентской ссылки.
- `origin` — домен твоего VPS, куда CDN отправляет запросы. У провайдера укажи этот HTTPS-origin и Host `node.example.com`, чтобы Caddy выбрал нужный сайт. Сохрани исходный XHTTP-путь при пересылке. Если пропустить `origin`, запись возьмёт `origin_domain` или, по умолчанию, `node.<domain>`.
- `path` — путь XHTTP, общий для клиента, Caddy и инбаунда. Можно указать свой или написать `generate`. После установки сгенерированный путь будет в рабочем `config.yml`.
- `port` — внутренний порт Xray. Обычно его можно опустить. Для первой записи утилита берёт `8080`.

### Несколько CDN

Добавь ещё одну запись с её `provider` и `edge`. При общем `origin` у каждой записи должен быть свой непересекающийся `path`. Если порты опущены, записи по порядку получат `8080`, `8081` и дальше. Например, вторая запись может использовать `edge2.example.com` и `path: generate`. [Пример YAML для двух CDN](../config.example.yml)

| Поле             | Режим HTTPS | Формат и значение по умолчанию                                                      | Когда заполнять и что меняется                                                                                                                                                         |
| ---------------- | ----------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cdn`            | `caddy`     | Список. По умолчанию `[]`.                                                          | Каждый элемент добавляет отдельный XHTTP-бэкенд. В режиме `certbot` поле можно опустить или задать `[]`.                                                                               |
| `origin_domain`  | `caddy`     | Доменное имя. По умолчанию `node.<domain>`.                                         | Имя origin, которое используют записи без собственного `origin`.                                                                                                                       |
| `cdn[].provider` | `caddy`     | `selectel` или `yandex`.                                                            | Обязательный выбор шаблона провайдера.                                                                                                                                                 |
| `cdn[].edge`     | `caddy`     | Доменное имя.                                                                       | Обязательный публичный адрес CDN для клиента.                                                                                                                                          |
| `cdn[].origin`   | `caddy`     | Доменное имя. По умолчанию `origin_domain`.                                         | Адрес сервера, к которому обращается CDN. Должен отличаться от доменов панели и подписок. Если общего origin нет, укажи его в каждой записи.                                           |
| `cdn[].port`     | `caddy`     | Целое число. По умолчанию `8080` для первой записи, затем `8081`, `8082` и далее.   | Локальный порт Xray для этого CDN.                                                                                                                                                     |
| `cdn[].path`     | `caddy`     | Путь с начальным `/` или `generate`. По умолчанию `/media/hls/9636f214/index.m3u8`. | Caddy передаёт запросы на этот путь и вложенные пути в Xray. Путь должен содержать хотя бы один сегмент. Для одного origin маршруты не должны совпадать или быть вложены друг в друга. |
| `cdn[].remark`   | `caddy`     | Непустая строка. По умолчанию примечание из шаблона.                                | Примечание инбаунда и соответствующей записи внешнего прокси.                                                                                                                          |
| `cdn[].tag`      | `caddy`     | Непустая строка.                                                                    | Тег нового инбаунда или точный тег для поиска существующего. Если при создании поле опущено, используется тег из пользовательского шаблона или `cdn-<provider>-<внешний порт>`, например `cdn-yandex-443`.                                                                                                   |

В теге используется порт клиента из шаблона CDN (`externalProxy[0].port`). Если в конфигурации несколько маршрутов одного провайдера, к автоматически сгенерированному тегу добавляется короткий суффикс по маршруту.

Установщик настраивает Caddy и Xray на VPS. DNS для доменов и настройки CDN нужно задать отдельно у своих провайдеров.

## Шаблоны инбаундов

В JSON-шаблонах лежат настройки протокола. Например, у прямого XHTTP можно изменить `streamSettings.xhttpSettings.mode`, у TCP REALITY — `sniffing.enabled`, а у любого инбаунда — `remark`.

| Ключ в `inbound_templates` | Какой инбаунд | Шаблон по умолчанию |
| --- | --- | --- |
| `reality` | TCP REALITY | [reality.json](../setup3ui/assets/templates/reality.json) |
| `direct_xhttp` | Прямой XHTTP REALITY | [direct-xhttp.json](../setup3ui/assets/templates/direct-xhttp.json) |
| `selectel` | XHTTP для Selectel | [selectel.json](../setup3ui/assets/templates/selectel.json) |
| `yandex` | XHTTP для Yandex | [yandex.json](../setup3ui/assets/templates/yandex.json) |

Скопируй нужный шаблон на сервер, измени нужные поля и укажи абсолютный путь в YAML. Можно указать только те шаблоны, которые хочешь заменить. При запуске через `curl` файлы по этим путям тоже читаются с сервера, где работает установщик.

```yaml
inbound_templates:
  direct_xhttp: /etc/setup-3x-ui/templates/direct-xhttp.json
```

Порты, адрес прослушивания, теги REALITY, SNI, XHTTP-путь и адрес CDN установщик подставляет сам из YAML и схемы подключения. Ключи REALITY и short IDs он генерирует при создании, а список клиентов оставляет пустым.

Шаблоны применяются при создании инбаунда, в том числе после сброса базы или при добавлении CDN. Уже созданный инбаунд редактируется в 3x-ui. При применении изменений маршрута CDN установщик ищет инбаунд по `cdn[].tag` и сохраняет его тег. При восстановлении из бэкапа используются сохранённые инбаунды.

## Одноразовые операции

| Поле | Режим HTTPS | Допустимые значения | Что делает |
| --- | --- | --- | --- |
| `action` | Оба | `install`, `restore`, `reset`. По умолчанию `install`. | `install` устанавливает, а при наличии рабочей конфигурации применяет её изменения. `restore` заменяет базу существующей установки. `reset` создаёт новую базу после резервного копирования текущей. |
| `backup_file` | Оба | Абсолютный путь к SQLite-бэкапу или каталогу резервной копии. | С `action: install` поднимает новую установку из копии. С `action: restore` импортирует её в существующую установку. |
| `confirm` | Оба | `true` или `false`. По умолчанию `false`. | `true` явно подтверждает замену базы при `restore` или `reset` без интерактивного подтверждения. |


Для восстановления укажи путь к бэкапу. Утилита проверит SQLite-файл и перенесёт логин, пароль, 2FA, клиентов и инбаунды. Исходная панель может быть выключена. При замене установки утилита сохраняет копию базы назначения, останавливает панель и применяет бэкап. Домены, порты, сертификаты и пути действующей установки сохраняются. Для чистой установки пути берутся из бэкапа. Если в восстановленной базе включена 2FA, введи свежий код при входе в веб-интерфейс.

При редактировании инбаундов в уже работающей панели с включённой 2FA утилита запрашивает код прямо в терминале. В YAML передавать его не нужно.

## Пример Certbot с TCP REALITY

```yaml
https: certbot
domain: vpn.example.com
email: ops@example.com
admin_username: vpn-admin
admin_password: "замени на свой пароль"
reality: true
```

Панель и подписки обслуживает 3x-ui на портах `2053` и `2096`. Xray принимает TCP REALITY на внешнем `443`.

## Пример без CDN

```yaml
https: caddy
domain: vpn.example.com
email: ops@example.com
admin_username: vpn-admin
admin_password: "замени на свой пароль"
reality: true
direct_xhttp: true
```

Получатся домены `master.vpn.example.com` и `gateway.vpn.example.com`. Клиенты TCP REALITY приходят на внешний `443`, прямого XHTTP REALITY — на внешний `8443`.

Проверить входной файл без установки можно командой `./setup-3x-ui validate --config /absolute/path/config.yml`. Проверка отклоняет дубли ключей и неизвестные поля. `--force` разрешает пропустить неизвестные поля с сообщением.
