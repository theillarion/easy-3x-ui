# Готовый образ Caddy в GHCR

**Статус** В работе. Реализация добавлена, первую публикацию в GHCR предстоит проверить. [Как публикуется и используется образ](../../docs/testing.md#выпуск-версии).

## Проблема

Если на новом VPS ещё нет нужного образа, установщик собирает Caddy с модулем Layer 4 прямо на сервере. В тестовой установке на VPS сборка заняла около пяти минут. При этом один образ подходит для всех конфигураций Caddy, которые генерирует утилита.

## Реализация

- При выпуске версии собирать образ из [Caddy.Dockerfile](../../setup3ui/assets/Caddy.Dockerfile) и публиковать его в GitHub Container Registry (GHCR) для Linux `amd64` и `arm64`.
- Указывать в установщике конкретную версию образа. Использовать локальный образ или скачать сборку этого Dockerfile из GHCR. Если скачивание не удалось, собрать образ локально.
- По-прежнему генерировать Caddyfile на VPS. Домены, порты, SNI, маршруты XHTTP и сертификаты задаются для каждой установки отдельно.
- Научить `update --component caddy` скачивать образ новой версии и сохранить возможность отката.

## Проверки

- Образ одной версии скачивается и запускается на Linux `amd64` и `arm64`.
- На чистом VPS установка с Caddy скачивает образ и обходится без `docker build`.
- Один образ работает с двумя разными конфигурациями. Проверить HTTPS панели и подписок, а также TCP REALITY на общем внешнем порту.
- При сбое обновления возвращается прежний образ Caddy и сервис снова работает.
