How the gateway works

Ingest, package, cache, deliver. Four stages, each observable on its own.

1

Ingest

An origin publishes a playlist and its segments. The gateway accepts CMAF, TS and fragmented MP4.

2

Package

Segments are re-indexed and, when requested, repackaged into HLS or DASH without re-encoding.

3

Cache

Objects land on the nearest edge with a short TTL. Cache state is reported per request.

4

Deliver

Players pull over HTTP/2 or HTTP/3 with byte-range requests for fast seeking.

Origin shielding

A single edge is promoted to shield for each region. Misses collapse into one upstream request per object, which keeps small origins from being overwhelmed during a live event.

Request collapsing

Concurrent requests for the same segment are held behind a single upstream fetch and released together, so a thousand viewers cost one origin round trip.

Graceful degradation

If an edge loses its upstream it keeps serving cached segments and marks the region degraded rather than failing the playback session outright.

Observability

Every request carries an edge identifier, cache state and upstream timing, exposed both in the log stream and on the status page.
