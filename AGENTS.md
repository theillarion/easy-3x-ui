# easy-3x-ui

Установщик 3x-ui для Debian 12 и 13. Работает с системным Docker и Docker Compose. Поддерживает Certbot, Caddy с Layer 4, TCP REALITY, прямой XHTTP REALITY и XHTTP через CDN.

## Решения и согласование

- Следуй указаниям пользователя по текущей задаче и сверяйся с локальным `decisions.md`, если он доступен. Локальные рабочие планы держи в `drafts/`, идеи будущих фич — в `features/`.
- **Запрещено создавать, изменять или удалять файлы и настройки без прямого поручения пользователя выполнить конкретное изменение.** Даже при наличии поручения запрещено выходить за его пределы.
- **Запрещено считать поручением на правку вопрос, сообщение об ошибке, замечание, указание на упущение, уточнение предмета разговора или описание ожидаемого поведения.** Например, «Почему скрипт не запускает Reality Scanner?», «Как сделать, чтобы он запустил сканер?» и «Я говорю про скрипт» требуют ответа по существу. Допустимы проверки, которые ничего не меняют. Прямое поручение на правку выглядит так: «Добавь запуск Reality Scanner в установщик».
- Изменения архитектуры, миграций, публичных интерфейсов и поведения на рабочем сервере, которые выходят за рамки задачи, сначала согласуй с владельцем.
- Если в корне есть `.codegraph/`, при разборе кода сначала используй CodeGraph. Индексирование запускай по запросу пользователя.

## Границы проекта

- Основной способ установки — запуск корневого `install.sh` через raw-ссылку GitHub. Он скачивает исходники сам. Тот же скрипт можно запустить из локальной копии проекта.
- Установщик настраивает конкретный узел. Управление главной панелью и создание VPN-клиентов остаются за пользователем.
- При восстановлении SQLite-бэкапа переносится его база. При замене действующей установки сначала нужны явное подтверждение, резервная копия и остановка панели. Установщик восстанавливает данные из файла без входа в старую панель.
- Не сохраняй реальные пароли, токены, секреты 2FA и клиентские ссылки в репозитории. Для примеров используй документационные домены.
- Установку, обновление, сброс, удаление и работу с рабочими серверами запускай по явному поручению. Если поручено проверить штатный установщик, используй его без ручной подгонки серверной конфигурации. При сбое сообщи точный этап и ошибку.

## Соглашения

- Пользовательская документация — на русском. Комментарии в коде, сообщения скриптов и логи — на простом английском.
- Подробный справочник YAML держи в [docs/configuration.md](docs/configuration.md). [docs/README.md](docs/README.md) — оглавление документации.
- Сохраняй поддержку Python 3.11 на Debian 12. Раскладывай код по назначению, как описано в [структуре проекта](docs/project-layout.md).
- При изменении YAML или поведения установки сверяй валидатор, примеры и документацию. Для регрессий добавляй подходящие тесты.

## Какие тесты писать

| Если меняешь | Добавь проверку |
| --- | --- |
| Валидацию YAML, порты, теги, разбор подписок или генерацию конфигов | Unit-тесты на допустимые значения, границы и ошибки. |
| Обращения к Docker, DNS, NTP, systemd или API | Тесты со сбоями и таймаутами через моки. Проверяй вызовы, повторный запуск, сохранение данных и откат. Моки могут использоваться в unit- и функциональных тестах. |
| CLI, shell-загрузчик, установку или самообновление | Функциональный тест через штатную команду в песочнице. Проверяй код выхода, установленные файлы, повторный запуск и отсутствие секретов в выводе. |
| Запуск Caddy, Certbot, 3x-ui, Xray, восстановление или маршруты | Интеграционный тест с реальными компонентами в выделенной Docker-сети. Для ACME используй тестовый CA Pebble. |

Чистая установка, повторный запуск, восстановление с 2FA и откат должны проходить полностью. Смена режима, инбаундов или способов установки требует проверки соответствующего сценария. Песочница использует отдельный Docker daemon без доступа к Docker-сокету хоста. Рабочие VPS в этот набор не входят.

## Проверки и покрытие

- Быстрые проверки запускаются командой `python3 -m unittest discover -s tests`.
- Полный набор запускается командой `./tests/sandbox/run.sh` в песочнице Debian 13. Он объединяет покрытие производственного Python-кода `setup3ui` и требует **не менее 95% строк и не менее 95% ветвей**. Процент считают по каждому из этих двух показателей отдельно. Shell проверяют сценариями, а не метрикой Python.
- Для правок документации проверь ссылки и затронутые команды. Для shell-скриптов проверь синтаксис через `sh -n`. Для генераторов дополнительно запусти `validate`, `render-caddy` или `render-compose` с `config.example.yml`.
- Перед завершением сверяй изменения и новые файлы. Если каталог под Git, используй `git status --short`, `git diff` и `git diff --check`. В итоговом сообщении указывай результат тестов и фактическое покрытие. Порог и необоснованные исключения не меняй ради прохождения тестов.

## Публикация

Заметные изменения записывай в `[Unreleased]` в [CHANGELOG.md](CHANGELOG.md). Используй SemVer.

Коммит, push, теги и релизы выполняй только по явной команде владельца. Если после push есть обязательные проверки GitHub Actions, дождись их результата для отправленного коммита. Избегай переписывания истории и force-push без отдельного поручения.
